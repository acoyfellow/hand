How it works

1. Listdo reads the screen's buttons and fields through the Mac's accessibility API.
→
2. PickClef, a small Cloudflare model, picks one and gives a probability.
→
3. Actdo presses or fills it. Unsure? It stops. Destructive? It asks first.
→
4. CheckClef checks the screen changed the way it should. Then the next step.

A bigger writer model is called only when the task needs text that isn't in it already, like turning "jordan at cloudflare dot com" into an email address.

Use it with an AI agent (MCP)

Give Claude, Pi or any MCP client your Mac. It gets six tools: apps, activate, outline, act, type, look.

bun add github:acoyfellow/do
swiftc -O node_modules/do/native/ax.swift -o node_modules/do/native/ax

Build the helper once, then allow Accessibility for your terminal in System Settings. Add this to your MCP client:

{ "mcpServers": { "do": { "command": "bun", "args": ["node_modules/do/src/mcp.ts"] } } }
  • Safe by default: it acts through accessibility, so it never moves your mouse or types into the wrong window. Real keystrokes need DO_HEADED=1.
  • It checks its own work: typed text is read back from the field. If the screen changed since it looked, it refuses and looks again.
  • Several agents can share one Mac: pass an agent id and they take turns.
  • Every action leaves a receipt: whether it landed, whether it was checked, and how.

Use it from code

import { gatewayTransport } from 'do/clef';
import { readConfig, readToken } from 'do/credentials';
import { macosDevice } from 'do/devices/macos';
import { Hand } from 'do/hand';

const transport = gatewayTransport({ ...readConfig(), token: readToken() });
const device = macosDevice({ helper: './ax', app: 'Google Chrome' });
const hand = new Hand(transport, device, {
  model: 'clef', method: 'ax_text', verify: true,
  tau: 0.3, riskTau: 0.5, injectionTau: 0.5,
});

await hand.act('switch to the termlab tab');
→ Clicked radio "termlab — web terminal benchmark" (p=0.86).
await hand.type('coey.dev', 'the address bar');
→ Typed into textbox "Address and search bar" (p=0.97).
await hand.look('Is coey.dev open?');
→ p(yes)=0.99

Needs a Cloudflare AI Gateway account, gateway name and token, read the same way as odds. The helper is built with swiftc -O node_modules/do/native/ax.swift -o ax.

What this does not show yet

  • The test app is easy to read: every control has a label. Canvas apps, unlabelled icons and misleading labels aren't tested.
  • The Mac support is new. It has been used on Chrome, Finder, Notes and TextEdit, but there's no scored set of Mac tasks yet.
  • One app, 30 tasks. Treat differences under about 3 tasks as noise.
  • The Opus numbers are from an older run and haven't been repeated.
  • macOS only. No command-line tool, no Windows or Linux yet.

Writer models

Scored alone on 44 messy requests. The default pairs a cheap model with a backup: glm-5.3-flash, then kimi-k2.6 for any field it leaves empty. 42–43 of 44 across runs, at $0.00009 a request. All writers.

The benchmark

Every change to the library has to pass a fixed benchmark: 30 tasks in a test app, success read from the app's own state, and a gate that fails if results get worse.

bun run check   # types, lint, tests
bun run gate    # fails if results are stale or worse
bun run bench   # real models, writes bench/runs/<id>/
